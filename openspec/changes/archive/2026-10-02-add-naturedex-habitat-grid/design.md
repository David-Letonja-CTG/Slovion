# Design

## Context

What exists today, from `add-meadow-walking-skeleton`, `add-species-identification` and `add-habitat-search`:
- `NatureDexService` returns the save's discoveries, oldest first.
- `naturedex-panel` renders them as one scrolling list of entries, using the observed/identified staging (D1).
- Habitats are content (`content/habitats/`), and every meadow species is listed in `tall_grass`.
- `ContentFilesSetup` serves `maps` and `tilesets` publicly; species JSON is deliberately not served (D7).
- `play-screen` routes UI actions to the open overlay. The identification dialog already handles `MoveUp`/`MoveDown`/`Confirm`/`Cancel`.
- The meadow tileset and player sprite are original pixel art, generated by a throwaway script.

Motivation: see proposal.md. Requirements: the three spec deltas.

Relies on these decisions:
- **D1:** names stay hidden until identified.
- **D3:** the client is trusted.
- **D6:** pictures and gameplay labels are not facts.
- **D7:** content as files, localized.
- **D10:** original IP.

## Goals / Non-Goals

**Goals:**
- A journal that reads as a collection: what you have, what is missing, and where to look.
- No information leak in the UI: unknown species show no name, group or facts.
- Keyboard, pointer and touch all work, consistent with the identification dialog.

**Non-Goals:** see proposal.

## Decisions

### 1. Species pictures

- **File and size:** one PNG per species in `content/species-pictures/<speciesId>.png`, 32×32 px, transparent background.
- **Serving:** `species-pictures` is added to `ContentFilesSetup.PublicFolders`, so it is served at `/content/species-pictures/`. Maps already work this way, and the dev proxy already forwards `/content`.
- **Validation:** `FileContentCatalog` checks that every species has a file whose first bytes are the PNG signature followed by an `IHDR` chunk of width 32 and height 32. It reads those 24 bytes itself; no image library is added. Like every other content error, a failure names the species.
- **One file, three states:** a single file per species. The three states are CSS filters on the same image, so there is no second "silhouette" asset to keep in sync:
  - unknown: `brightness(0)` at reduced opacity
  - observed: `grayscale(1)`
  - identified: no filter
- **Rendering:** `image-rendering: pixelated`, scaled ×2 in the grid and ×3 on the species page.
- **Art source:** drawn by a throwaway generator script in the same palette as the meadow tileset, like the existing art. The PNGs are the source of truth and can be edited in any pixel editor. Colours and shapes follow each species' sourced characteristics:

  | Species | Picture |
  |---|---|
  | swallowtail | yellow wings with black veins and tail points |
  | meadow sage | blue-violet flower spike |
  | hare | brown body with long black-tipped ears |
  | skylark | streaked brown bird with a small crest |
  | dandelion | yellow flower head with a toothed leaf rosette |

  The owner reviews the five pictures in the pull request.

### 2. Habitat names

Habitat files gain localized text, mirroring species text:

```json
{ "id": "tall_grass", "text": { "sl": { "name": "Visoka trava" } }, "searchChancePercent": 70, "species": [ … ] }
```

- `Habitat` (domain) gains `IReadOnlyDictionary<string, string> Names`, keyed by language.
- Validation requires `sl` and a non-blank name.
- Lookup uses the negotiated content language and falls back to Slovenian, like `SpeciesView.TextFor`.
- The name is a game label and needs no source.

Validation also requires every species to appear in at least one habitat. This is a cross-file check after loading both species and habitats, and the error names the species.

### 3. API shape

`GET /api/save/naturedex` (breaking; the client changes in the same PR):

```json
{
  "habitats": [
    {
      "habitatId": "tall_grass",
      "name": "Visoka trava",
      "species": [
        { "speciesId": "lepus_europaeus", "status": "unknown", "entry": null },
        { "speciesId": "salvia_pratensis", "status": "identified",
          "entry": { "speciesId": "salvia_pratensis", "group": "plant", "status": "identified",
                     "observedAt": "…", "identifiedAt": "…", "species": { … } } }
      ]
    }
  ]
}
```

- **Entry type:** each item wraps the existing `NatureDexEntryResponse` unchanged. That type is also returned by the answer and "already identified" responses, so its fields stay non-nullable and no second entry type exists.
- **Status for unknown species:** `status` is explicit, so the client never infers "unknown" from a missing entry.
- **Section order:** sections are ordered by habitat ID (ordinal); species keep the habitat file's order. `add-first-quest` adds a second habitat and may introduce an explicit order if ID order reads badly.

`IContentCatalog` gains `AllHabitats`. `NatureDexService.GetAsync` returns `IReadOnlyList<NatureDexSection>`, where:
- `NatureDexSection(string HabitatId, string Name, IReadOnlyList<NatureDexSlot> Species)`
- `NatureDexSlot(SpeciesId SpeciesId, NatureDexEntry? Entry)`

It reads the discoveries once, builds a dictionary by species, and maps each habitat's species list through it. Discoveries of species no longer in content are skipped, as today; the record stays in the database.

### 4. Panel views

`NatureDexPanel` keeps loading and error handling and gains a view signal: `grid`, `card(speciesId)` for observed species, or `page(speciesId)` for identified ones.

- **Grid:**
  - one `<section>` per habitat, with an `<h3>` holding the name and the `identified/total` count
  - a list of picture buttons in a CSS grid of **5 fixed columns**; tiles shrink on narrow screens, and pictures stay pixelated
  - each button holds the `<img>` (alt empty, decorative) and a label element
  - the label is visible on `:hover`, on `:focus-visible` and on the selected button
  - `aria-label` is the name for identified species and *Neznana vrsta* otherwise
  - unknown buttons have `aria-disabled="true"` and ignore clicks, but stay focusable so keyboard selection can pass over them
- **Card and page:** the existing markup for unknown and identified entries moves into these views, which add the picture and a *Nazaj* button. Opening a view focuses *Nazaj*. Returning to the grid focuses the previously selected button.
- **Empty journal:** when no species is observed or identified, the existing `naturedex.empty` message is shown above the grid.

### 5. Keyboard selection

A pure function in `naturedex-selection.ts` returns the next selection: `move(sectionSizes: number[], current: {section, index}, action) → {section, index}`. It is unit-tested on its own, with no DOM layout needed, because the column count is fixed at 5.

- `MoveLeft`/`MoveRight`: previous or next picture in reading order, crossing sections and stopping at the ends.
- `MoveUp`/`MoveDown`: ±5 within a section. At a section edge, the selection moves to the same column in the adjacent section's last or first row, clamped to that row's length. At the journal's top or bottom it stays put.

`play-screen` forwards UI actions to the panel's `handleAction`, as it does for the identification dialog. `Cancel` goes from a view back to the grid; in the grid it emits `closed`. The selected button receives DOM focus, which also scrolls it into view.

### 6. UI text (`sl.json` additions)

| Key | Text |
|---|---|
| `naturedex.progress` | `{{ identified }}/{{ total }}` |
| `naturedex.unknownLabel` | `???` |
| `naturedex.back` | *Nazaj* |

The existing `naturedex.unknown` (*Neznana vrsta*) is reused as the accessible label for unknown and observed pictures. The existing `naturedex.empty` text stays as it is.

## Implementation notes (review, task 4.4)

The owner approved the proposal on 2026-10-02. Every changed file was reviewed against the non-goals and every scenario in the three spec deltas. Each scenario is covered by a content-validation, application, integration, client or E2E test. The *Identifying the hare colours it* scenario is tested with the sage, which is the same behaviour for a different species. No non-goal was touched: there are no numbers, filters, rarity values or new stages.

The manual check at 1280×720 and 390×844 found two layout problems, both fixed:
- **Species page scroll:** focusing *Nazaj* at the bottom of a long page scrolled the panel down past the species name. *Nazaj* now sits at the top of the page and the card.
- **Tile height on phones:** a long name wrapped to three lines and made its tile taller than the others. Labels are now fixed at two lines, with a smaller font on narrow screens.

Other deviations and additions; none changes behaviour beyond the specs:
- **`Confirm` on an opened species** also returns to the grid, because it activates the focused *Nazaj* button.
- **Clicking or tapping a picture** moves the selection to it, so keyboard and pointer stay in sync.
- **Selection logic** lives in `naturedex-selection.ts`, a pure function. It skips sections with no species.
- **Tile background** `--color-tile`, a muted grass tone, keeps black silhouettes visible on the dark panel. It is local to the panel.
- **`EncounterServiceTests`** now check observations through the discovery repository rather than the NatureDex, which no longer lists discoveries directly.
- **Integration test helper `NatureDexEntriesAsync`** flattens the sections into the save's entries, once per species, so existing discovery tests keep their intent.
- **Content validation** skips the habitat-membership check when a habitat file is invalid. This avoids follow-on errors for every species of a broken habitat file.

## Risks / Trade-offs

- **Silhouettes reveal shapes:** this is accepted and intended as a light hint, the usual collection-game convention, using our own art.
- **Unknown species' IDs (scientific names) are visible in the response and the picture URLs.** This is accepted under D3: single-player and a trusted client, so there is nothing to gain by cheating. The UI never shows them.
- **Fixed 5 columns:** simple and testable keyboard movement, at the cost of fewer, larger tiles on wide screens. This is enough for the current journal size; the decision can be revisited when the journal grows.
- **Pixel art accuracy:** pictures are stylized illustrations. Recognizability is reviewed by the owner, and the pictures make no factual claims.
- **Breaking API change:** there is no external consumer. Client and server ship together.
